## 1. 设计原则

按序号优先，冲突时上位否决下位：

1. **确定优先于快速。** 归属判定必须是推理链的结论，不是概率猜测。
2. **不打断优先于完整。** 任何会关闭用户程序的行动，必须知情同意且可恢复。
3. **不失效优先于聪明。** 知识库、规则表都可能过期，核心能力不能依赖它们。
4. **可验证优先于看起来对。** 每个模块都能被单独证伪。

## 3. 两段式扫描

### 3.1 快扫（QuickScan）

| 项 | 规格 |
|---|---|
| 输入 | 无 |
| 动作 | 对 828 个候选组合逐一试注册 |
| 输出 | `takenKeys` 集合（**只有键，没有归属**） |
| 耗时 | < 1 秒 |
| 副作用 | 无（微秒级占用即释放） |
| 打断应用 | 否 |

快扫结果可直接填充「Windows 自带」tab —— 因为系统键由规则表按组合键直接映射到功能名，不需要知道是哪个进程注册的。

### 3.2 深扫（DeepScan）

| 项 | 规格 |
|---|---|
| 前置 | 用户已在确认对话框同意关闭清单 |
| 输入 | `takenKeys` + 候选进程列表 |
| 动作 | 遍历候选进程：关闭一个 → 复测所有未归因键 → 记录释放的键 → 恢复该进程 |
| 输出 | `unattributed → {进程: [键...]}` 完整映射 |
| 耗时 | 候选数 × 约 1.5 秒，典型 30–60 秒 |
| 打断应用 | **是，逐个（同一时刻最多 1 个被关闭）** |
| 可中断 | 是，已扫描部分保留 |

**为什么逐个而不是批量**：批量关闭（二分）虽快，但同一时刻会有多个程序消失，用户观感差、异常恢复更复杂。逐个扫描时任何时刻最多只有 1 个程序受影响，可随时中止，且每完成一个就能更新界面（渐进呈现）。

### 3.3 深扫算法

```
输入：takenKeys（未归因的键集合）, candidates（已过滤的候选进程）

1. 按权重降序排序 candidates：
      有可见窗口        +30
      有托盘图标        +20
      可执行文件在用户目录 +10
      知识库声明有热键习惯 +15（可选，知识库缺失时此项恒为 0）
      已知服务型组件    -20

2. for proc in candidates:
       if takenKeys 为空: break                    # 全部归因完成，提前结束
       if proc 已退出: continue                     # 每轮重新校验存活

       记录快照(proc)                               # 必须在关闭前落盘
       Act.GracefulClose(proc)  → 失败则 ForceKill
       等待 10 ms（H3 实测：释放即时，0 ms 即 100% 可靠；10 ms 为工程裕度）

       after = ProbeAll(takenKeys)
       released = takenKeys - after

       if released 非空:
           归属[proc] = released
           takenKeys = after

       Act.Restore(proc)                            # 立即恢复，不等扫描结束
       推送进度(已处理 i/N，剩余 |takenKeys| 个键未归因)

3. 若 takenKeys 仍非空 → 标记为「无法归因」（可能属已退出进程 / PPL 保护进程 / 系统隐藏组件）
```

**关键约束**：

| 约束 | 理由 |
|---|---|
| 关闭前必须落盘快照 | 进程崩溃或工具被强杀时，仍能恢复 |
| 立即恢复而非最后统一恢复 | 缩短单个应用不可用时长；中断扫描也不会留下大量未恢复进程 |
| 等待 10 ms 再复测 | H3 实测：热键释放随进程退出**即时完成**（0 ms 即 100% free，12 次重复），10 ms 为工程裕度。原 300 ms 估计过保守 |
| 每轮重新校验存活 | 用户在扫描期间可能自己开了/关了程序 |

### 3.4 候选进程过滤（安全闸门）

四道过滤，顺序不可调换：

| 顺序 | 过滤 | 规则 |
|---|---|---|
| 1 | 硬禁止 | 系统关键进程：`explorer` `dwm` `csrss` `winlogon` `lsass` `wininit` `services` `svchost` `fontdrvhost` `ctfmon` |
| 2 | 硬禁止 | 反作弊组件：EAC / BattlEye / Vanguard / ACE / mhyprot / nProtect / XignCode / Ricochet / Javelin |
| 3 | 排除 | 自身进程、前台全屏应用（用户正看着，不能突然消失） |
| 4 | 分类 | 剩余按权重排序，权重仅影响顺序，不影响资格 |

**反作弊名单必须硬编码**，不得来自可编辑文件。理由：用户误删一条，就可能结束掉反作弊服务，导致封号或游戏崩溃。

### 3.5 快速识别模式（可选，默认关闭）

**用途**：在不关闭任何程序的前提下建立归属映射。是"深扫会打断应用"的直接对治。

**原理**：热键被按下时，系统向注册者投递 `WM_HOTKEY`。只要能看到"谁收到了"，就等于知道了归属——不需要关闭它。

```
1. 环境闸门（任一不满足则拒绝启用）
   ├─ 当前进程已提权？（v3.2 起启动即 requireAdministrator，故恒成立，保留作防御性校验）
   ├─ 检测到反作弊进程在运行？是 → 禁用本模式并说明原因
   └─ 用户已阅读并确认风险说明？否 → 弹出说明，退出

2. 注入钩子
   ├─ 枚举会话内所有 GUI 进程，按位数分为 x64 / x86 两组
   ├─ 硬排除：游戏进程、反作弊组件、屏幕阅读器（无障碍工具除外原则）
   └─ 分别注入钩子 DLL（WH_GETMESSAGE），DLL 内捕获 WM_HOTKEY
       并通过共享内存回传 {PID, 修饰键, 虚拟键码}

3. 逐个模拟按键
   for combo in 未归因键集合:
       SendInput 按下修饰键 → 按下主键 → 释放主键 → 释放修饰键
       等待 200 ms 收集回传
       若收到归属 → 记入映射

4. 收尾（必须执行，即使异常）
   ├─ 卸载所有钩子
   ├─ 强制释放所有修饰键状态（防止 Alt/Ctrl 卡住）
   └─ 汇总映射，标注未识别的键
```

**安全检查清单**（代码级，不可配置）：

| 检查 | 动作 |
|---|---|
| 目标是游戏进程或反作弊组件 | **不注入**，即使因此漏报 |
| 目标是屏幕阅读器 | **不注入**（注入出错可能让视障用户失去语音） |
| 模拟按键前 | 保存当前修饰键状态，结束后强制释放 |
| 检测到反作弊加载 | 立即卸载全部钩子并退出本模式 |
| 模式运行中 | 禁用「深扫」入口，避免两套流程并行 |

**必须向用户事先说明的副作用**：

> 这个模式会模拟按下每个热键，因此**占用者的功能会被真的触发**——微信会弹出截图框、录屏软件可能开始录制、音乐播放器会切歌。它不关闭任何程序，但不是"零打扰"。

**与深扫的取舍**：

| | 深扫 | 快速识别 |
|---|---|---|
| 关闭程序 | 会（逐个闪退） | 不会 |
| 打扰形式 | 程序闪退再启动 | 屏幕上一堆窗口闪一下、功能被触发 |
| 权限 | 普通 | 管理员 |
| 杀软/反作弊风险 | 低 | 高 |
| 受保护进程 | 查不到（无法结束） | 查不到（无法注入） |
| 耗时 | 10–40 秒 | 2–5 秒 |

两者**对受保护进程都无能为力**，这是共同的天花板。

## 4. 单键快查（保留 v2 能力）

用户按下一个键，快速回答"它被谁占了"。

**与深扫的关系**：若已有深扫结果，直接查表（0 秒）；若没有，走"探测 + 定向定位"：

```
probe(combo)
├─ Free   → 结论 C：系统层面无冲突（钩子/IME/游戏内绑定）
└─ Taken  → 若已有映射：查表返回
            若仅快扫过：对候选做定向遍历（只测这一个键，命中即停）
```

定向遍历比深扫快得多，因为它命中即停，且只关心一个键。

## 5. 归因辅助模块

### 5.1 系统规则表（必须保留）

两张静态表，与知识库性质不同——它们是**判定逻辑**，不是**事实数据**，不需要跟着软件版本维护。

| 表 | 内容 | 用途 |
|---|---|---|
| 系统保留键 | `Ctrl+Alt+Del` `Alt+Tab` `Alt+F4` `Win+L` `Win+D` `Win+R` `Win+E` 等 | 归入系统 tab，标注"不可禁用" |
| 系统功能键 | `Win+G` Game Bar、`Win+V` 剪贴板、`Win+H` 语音、`Win+P` 投影 | 归入系统 tab，标注可关闭路径 |

每条含 `category` 字段（窗口管理 / 系统 / 输入 / 截图录制 / 辅助功能），用于树状视图分组。

### 5.2 进程分类器（替代知识库做 tab 分类）

判断"这是不是 Windows 自带"，**不靠软件名单，靠两个客观特征**：

```
是系统进程 ⟸ 路径以 %SystemRoot%\ 开头  且  有微软签名
```

优点：未来新装任何软件都能正确分类，不需要维护。

### 5.3 知识库（可选增强，不参与定位）

| 项 | 规格 |
|---|---|
| 是否必需 | 否。缺失、损坏、过期时功能完整 |
| 仅做两件事 | ① 提供 `disableHint`（去哪永久关闭）② 给候选排序 +15 权重 |
| 加载失败 | 静默降级，不提示错误 |
| 位置 | 与 exe 同目录 `kb.json`，用户可编辑 |

### 5.4 安全闸门 Guard（提权后必须绝对化）

```csharp
public enum RiskLevel { Safe, Caution, Forbidden }
public RiskLevel Evaluate(ProcInfo p);
```

| 判定 | 含义 |
|---|---|
| `Forbidden` | 永不进入任何关闭或注入流程（含深扫、定向定位、快速识别） |
| `Caution` | 有可见窗口，深扫前需在清单中明示，可被用户取消勾选 |
| `Safe` | 无窗口后台进程，可直接纳入深扫 |

**v3.2 附加约束（因为程序现在以管理员运行）**：

> 提权状态下，一次误判的后果不再是"关掉一个软件"，而是"会话崩溃"或"账号被封"。因此闸门必须从"尽力拦截"升级为"绝对拦截"。

| 约束 | 理由 |
|---|---|
| Forbidden 名单为编译期常量，每个条目有单元测试覆盖 | 不接受运行时配置，避免被误改 |
| 任何关闭/注入请求必须先过 `Guard.Evaluate` | 禁止绕过直接调用 `ProcessController` |
| 不提供"忽略警告继续"入口 | 高权限工具不该给用户一条通往灾难的捷径 |
| 修改名单需重新编译并跑全量测试 | 防止随手加个白名单条目 |

**证据字段 `evidence` 是诚实性的载体**：UI 上要能区分"规则判定"、"实测遍历"与"知识库推测"，前两者是确定性的，后者不是。

## 8. 状态机

```
        ┌──────┐
        │ Idle │
        └──┬───┘
   启动   │
        ┌─▼──────────┐
        │ QuickScan  │  828 组合探测，< 1 秒
        └─┬──────────┘
          │
     ┌────▼──────────────────────────┐
     │ QuickDone                     │
     │ · 系统 tab 已填充（规则表）     │
     │ · 其他应用 tab 只显示数量       │
     └────┬──────────────────┬───────┘
          │ 用户点「深度扫描」  │ 用户按下某个键
     ┌────▼─────────┐   ┌────▼─────────┐
     │ Confirming   │   │ SingleLookup │
     │ 列出关闭清单  │   │ 探测+定向定位 │
     └────┬─────────┘   └────┬─────────┘
          │ 同意              │
     ┌────▼─────────┐        │
     │ DeepScanning │        │
     │ 遍历归因      │        │
     │ 可中止        │        │
     └────┬─────────┘        │
          │                  │
     ┌────▼──────────────────▼───────┐
     │ Result（地图已完整 / 单键结论） │
     └────┬──────────────────────────┘
          │ 用户点「禁用」
     ┌────▼─────────┐
     │ Disposing    │  落盘 → 关闭 → 标记已禁用
     └────┬─────────┘
     ┌────▼─────────┐
     │ Done/Restorable│
     └──────────────┘
```

**状态约束**：

| 约束 | 理由 |
|---|---|
| `DeepScanning` 期间禁用「深度扫描」按钮与按键快查 | 避免两套流程同时关闭进程 |
| `Disposing` 必须原子完成：落盘 → 关闭 → 更新状态 | 任一步失败则回滚并提示 |
| 任何状态下关闭窗口，若有未恢复清单必须拦截确认 | 防止用户误以为程序还在 |
| `DeepScanning` 中止后保留已完成部分 | 避免用户白等 |

## 9. 处置层

| 动作 | 触发 | 可逆 | 风险 |
|---|---|---|---|
| `GracefulClose` | 深扫 / 用户禁用 | 是 | 低 |
| `ForceKill` | 优雅关闭超时（3 秒） | 是 | 中（可能丢未保存数据） |
| `Restore` | 扫描完成 / 用户点恢复 / 下次启动 | — | 无 |
| `GuideOnly` | 系统功能键、可选知识库命中 | — | 无 |

**处置优先级**：`GuideOnly > GracefulClose > ForceKill`。能引导就引导，因为它才是"永久解决"。

## 11. 失败模式与降级

| 失败 | 检测 | 降级 |
|---|---|---|
| 启动时 UAC 被拒绝 | `requireAdministrator` 启动失败 | 提示原因后**正常退出，不降级运行**。降级会让用户误以为"有些热键查不到是 bug" |
| 提权后仍打不开某进程（PPL） | `OpenProcess` 返回拒绝访问 | 标注「受保护，无法确认」，不计入错误 |
| 快速识别：注入被拒（受保护进程） | 注入返回失败 | 跳过该进程，标注「受保护，无法识别」 |
| 快速识别：修饰键卡住 | 收尾检查输入状态 | 强制释放全部修饰键 |
| 快速识别：运行中检测到反作弊 | 轮询进程列表 | 立即卸载全部钩子并退出本模式 |
| 探测返回非 1409 错误 | 错误码 | 标记"无法判定"，不参与归因 |
| 进程路径取不到 | API 返回空 | 用 exe 名分类，标注"信息不完整" |
| 进程无法结束（PPL 保护进程） | 错误码 5 | 跳过，条目标注「受保护，无法确认归属」。v3.2 提权后此类已大幅减少 |
| 优雅关闭超时 | 3 秒 | 强制结束（需在 UI 标注该进程被强制关闭） |
| 恢复失败 | 创建进程失败 | 提示完整路径与命令行，让用户手动启动 |
| 深扫中途工具崩溃 | 启动时检查快照 | 提示未恢复清单，一键恢复 |
| 用户中止深扫 | 用户点击 | 保留已完成结果，明确标注"未完成" |
| 所有候选都试完仍有未归因键 | 循环结束 | 标注未知，提示"可能属已退出进程或系统隐藏组件" |

## 12. 边界情况

| 情况 | 处理 |
|---|---|
| 深扫时用户自己开了新程序 | 每轮重新枚举，新程序不纳入本轮（标注"扫描后启动"） |
| 某进程关闭后立刻被守护进程拉起 | 复测时热键重新出现 → 归属仍成立（键回到 taken 说明是它），但需标注"有守护进程" |
| 两个进程注册同一功能的**不同**热键 | 遍历会分别归因，正常 |
| 进程用钩子而非注册 | 遍历时结束它，探测结果不变 → 不归因到它，也不列入地图（符合"只列注册热键"的定义） |
| PPL 保护进程注册了热键 | 即使管理员也无法打开 → 标注「受保护，无法确认」，不声称确定 |
| 用户在深扫中锁屏/休眠 | 探测与关闭可能失败 → 恢复后提示重新扫描 |
| 多用户会话 / 远程桌面 | P0 假设单用户单会话，多会话下热键表隔离，文档标注不保证 |

## 13. 接口契约

| 调用方 | 被调方 | 契约 |
|---|---|---|
| UI | Orchestrator | `QuickScanAsync() → HotkeyMap`，不产生副作用 |
| UI | Orchestrator | `DeepScanAsync(approveList, IProgress, CancellationToken) → HotkeyMap` |
| Orchestrator | Discover | `AttributeAsync(takenKeys, candidates) → Map<Proc, Keys>`，**必须**通过 Act 关闭 |
| Orchestrator | Act | `GracefulClose(proc) → Result`，内部强制先落盘快照 |
| Discover | Probe | `Probe(mods,vk) → Free｜Taken｜Error` |
| Discover | Guard | `Evaluate(proc) → Safe｜Caution｜Forbidden`，`Forbidden` 不得进入候选 |
| UI | KnowledgeBase | `LookupHint(exe, combo) → string?`，可为 null，缺失不影响渲染 |

**类型强制**：`KnowledgeBase` 只能返回 `string?`（提示文案）与 `int`（排序权重），**不得返回归属结论**。归属只能来自 `Discover`。这在类型层面守住了"知识库不参与定位"的纪律。

## 14. 待验证假设

| ID | 假设 | 验证方式 | 不成立的影响 |
|---|---|---|---|
| H1 | 钩子型占用时探测返回 `Free` 且按键无效 | 挂 `WH_KEYBOARD_LL` 吞键的子进程 + 探测 | 诊断矩阵需改写，需在文档中改口径 |
| H2 | 优雅关闭（`WM_CLOSE`）能释放热键 | 对注册热键的程序发 `WM_CLOSE` 后复测 | 只能强制结束，数据丢失风险升高，UI 需加确认 |
| **H3** | **热键释放需等待多久才能被复测到** | 关闭后按 0/100/300/1000 ms 分别探测 | 直接决定深扫耗时与准确性，**本次最关键** |
| H4 | 遍历 20 个进程后归属准确率 100% | 真实软件矩阵实测 | 若不达，需引入重试或排除某些进程类型 |
| H5 | PPL 保护进程注册热键的比例不高 | 在反作弊游戏运行状态下实测未归因键数 | 若占比高，"完整地图"的承诺需调整口径（改为"除受保护进程外完整"） |

> **H3 已验证（2026-10-20）**：热键释放随进程退出**即时完成**，0 ms 即 100% 可靠（12 次重复）。深扫每轮等待 10 ms（工程裕度）。原担心"300 ms 不够"不成立；瓶颈转为进程关闭/启动耗时，而非等待。
