## 3. 任务拆解

### 任务 0：验证 H3 — 热键释放延迟
- **文件**：`docs/实验记录.md`
- **要做**：写一个注册热键的子进程，结束它之后分别在 0 / 50 / 100 / 200 / 300 / 500 ms 时刻探测，记录热键何时变 `free`。重复 10 次取最坏值。
- **验证**：得到"最坏延迟"数值，写入设计文档 §3.3 的等待参数
- **为什么先做**：这个数值决定 `DeepScanner` 每轮等待多久。设小了会漏判（把 A 的键误判为无人占用），设大了 20 个进程就拖到 2 分钟

### 任务 1：工程骨架、提权清单与探测层
- **文件**：`HotkeyTriage.sln`、`src/HotkeyTriage.App/app.manifest`、`src/HotkeyTriage.Core/Probe/HotkeyProbe.cs`、`Interop/NativeMethods.cs`
- **要做**：
  - 建三个项目（Core / App / Tests）
  - 配置 `app.manifest`：`requestedExecutionLevel level="requireAdministrator" uiAccess="false"`
  - 封装 `RegisterHotKey`/`UnregisterHotKey`；`Probe(mods, vk)` 返回 `Free｜Taken｜Error`，`1409` 单独识别为 `Taken`；`try/finally` 保证注销
- **验证**：
  - 从**非管理员**命令行启动，断言弹出 UAC；点"否"后断言进程未启动、无残留
  - 提权后运行 `whoami /groups | findstr High` 断言为高完整性
  - 测试注册一个键 → `Probe` 返回 `Taken`；注销后 → `Free`；`dotnet test --filter HotkeyProbe` 全绿

### 任务 2：进程枚举与窗口检测
- **文件**：`src/HotkeyTriage.Core/Probe/ProcessScanner.cs`
- **要做**：枚举 PID / exe 名 / 完整路径 / 是否有可见主窗口 / 是否有托盘图标；路径取不到时降级不抛错
- **验证**：断言结果 > 100 条；断言能拿到自身路径；断言自身进程被标记为"有窗口"

### 任务 3：系统规则表
- **文件**：`src/HotkeyTriage.Core/Attribute/SystemRules.cs`
- **要做**：录入系统保留键与系统功能键，每条含 `category`（窗口管理/系统/输入/截图录制/辅助功能）与 `disposition`（reserved/disableable）与可选 `hint`
- **验证**：断言 `Alt+Tab` → `reserved`、`Win+G` → `disableable` 且 `hint` 非空、`Alt+A` → 不在规则表

### 任务 4：进程分类器
- **文件**：`src/HotkeyTriage.Core/Attribute/ProcessClassifier.cs`
- **要做**：用"路径在 `%SystemRoot%` 下 + 微软签名"判定系统进程；不依赖任何软件名单
- **验证**：断言自身进程 → 非系统；断言 `svchost`/`dwm` → 系统；构造一个 `%SystemRoot%\notepad.exe` 路径的假数据 → 系统

### 任务 5：快扫与数据模型
- **文件**：`src/HotkeyTriage.Core/Probe/KeyGrid.cs`、`Discover/QuickScanner.cs`、`Model/HotkeyMap.cs`
- **要做**：生成 828 组合网格；快扫产出 `takenKeys`；按规则表把系统键填充进 `HotkeyMap`，其余标记为 `third_party` 但 `owner = null`
- **验证**：断言快扫耗时 < 1 秒；断言系统 tab 条目全部有 `group` 与 `disposition`；断言第三方条目 `owner` 为空且 `evidence = none`

> **M2 里程碑到此结束**：此时应能打开程序，看到「Windows 自带」tab 的完整树，「其他应用」tab 显示数量。这是第一个可截图的状态。

### 任务 6：安全闸门
- **文件**：`src/HotkeyTriage.Core/Attribute/Guard.cs`
- **要做**：硬编码系统关键进程与反作弊名单；`Evaluate(proc) → Safe｜Caution｜Forbidden`
- **验证**：断言 `explorer.exe` / `vgc.exe` / `BEService.exe` → `Forbidden`；断言 `Weixin.exe` → `Caution` 或 `Safe`；断言名单是 `static readonly` 常量而非读文件

### 任务 7：进程关闭与恢复
- **文件**：`src/HotkeyTriage.Core/Act/ProcessController.cs`
- **要做**：`GracefulClose` 发 `WM_CLOSE` 并等 3 秒，超时升级 `ForceKill`；`Restore` 用记录的路径与参数重建进程
- **验证**：对记事本执行优雅关闭，断言 3 秒内退出；对无窗口进程断言走强制结束；结束后调用 `Restore`，断言进程重新出现

### 任务 8：禁用清单与恢复提示
- **文件**：`src/HotkeyTriage.Core/Act/DisabledListStore.cs`
- **要做**：关闭**前**落盘；启动时扫描 `restored: false` 条目；恢复后更新标记
- **验证**：人为让目录不可写，断言抛错且不执行关闭；模拟异常退出后重启，断言能列出未恢复项

### 任务 9：深扫核心（遍历归因）
- **文件**：`src/HotkeyTriage.Core/Discover/DeepScanner.cs`
- **要做**：按权重排序候选；逐个「落盘 → 关闭 → 等待(H3) → `ProbeAll(未归因键)` → 记录释放键 → 恢复」；`takenKeys` 清空则提前结束
- **验证**：用两个测试进程（分别注册不同的键）构造场景，断言两者被正确归因到各自 PID，且未归因集合为空；断言每个被关闭的进程都已恢复

### 任务 10：深扫中止与容错
- **文件**：`src/HotkeyTriage.Core/Discover/DeepScanner.cs`（续）
- **要做**：支持 `CancellationToken`，中止时立即恢复当前进程并保留已完成结果；进程中途退出、关闭失败、恢复失败均不中断整个扫描
- **验证**：扫到第 3 个时取消，断言当轮进程已恢复、前 2 个结果保留、返回结果标记为 `incomplete`；模拟关闭失败，断言跳过并继续

### 任务 11：单键快查
- **文件**：`src/HotkeyTriage.Core/Discover/SingleLookup.cs`
- **要做**：有映射则查表；无映射则对该键做定向遍历（命中即停）；`Free` 直接返回"无系统冲突"结论
- **验证**：`Free` 场景断言不触发任何进程关闭；`Taken` 且已有映射时断言 0 次关闭；无映射时断言命中后立即停止

### 任务 12：主窗口与树状视图
- **文件**：`src/HotkeyTriage.App/MainForm.cs`、`TreeRenderer.cs`
- **要做**：双 `TabControl`；系统 tab 按 `group` 分组；第三方 tab 按进程分组，未归属时显示引导文案与「深度扫描」按钮
- **验证**：构造含 200 条目的假数据，断言渲染 < 200 ms；断言系统 tab 分组正确；断言未归属状态下不显示任何"归属"字样

### 任务 13：深扫确认对话框
- **文件**：`src/HotkeyTriage.App/DeepScanDialog.cs`
- **要做**：列出将被关闭的进程（`Forbidden` 不出现）；有窗口的默认不勾选并标"可能有未保存内容"；底部说明"以下程序不会被触碰"
- **验证**：断言 `explorer.exe` 不在列表中但在"不会触碰"说明里出现；断言取消勾选的进程不进入扫描

### 任务 14：扫描进度与状态
- **文件**：`src/HotkeyTriage.App/MainForm.cs`
- **要做**：显示"已处理 i/N + 当前进程名 + 剩余未归因键数"；提供中止按钮；禁用状态互斥（扫描中不能再次扫描）
- **验证**：跑一次真实深扫，断言 UI 全程可拖动（不卡死）、进度文字每轮更新、中止按钮有效

### 任务 15：禁用与恢复交互
- **文件**：`src/HotkeyTriage.App/MainForm.cs`
- **要做**：进程节点上的「禁用」「恢复」按钮；状态标识 `运行中`/`已禁用`/`无法禁用`；关闭窗口时若有未恢复项需拦截确认
- **验证**：禁用微信后断言节点变「已禁用」且热键从列表中消失；点恢复后断言节点变回「运行中」

### 任务 16：知识库（可选增强）
- **文件**：`src/HotkeyTriage.Core/Attribute/KnowledgeBase.cs`、`assets/kb.json`
- **要做**：加载 JSON 提供 `hint` 与排序权重；缺失/损坏时静默降级为空库；**不得返回归属结论**；定位文件用 `AppContext.BaseDirectory`（**不能用当前工作目录**——提权启动后工作目录常变成 `System32`，会读不到 kb.json）
- **验证**：删除 kb.json 后所有功能正常、界面无报错；断言 `KnowledgeBase` 的公开方法只有 `LookupHint` 与 `Score`，无返回归属的类型

### 任务 17：打包发布
- **文件**：`build/publish.ps1`
- **要做**：单文件压缩发布；生成 SHA256；README 写明能力边界
- **验证**：干净机器（无 .NET 运行时）双击可运行；冷启动 ≤ 1.5 秒；体积 ≤ 50 MB

### 任务 18：矩阵测试与负例
- **文件**：`docs/测试记录.md`
- **要做**：按设计文档矩阵测 20 款软件；**必测负例**：AutoHotkey 脚本吞键（应不归因、不误报）、中文输入法激活（应给出"无系统冲突"）、管理员权限程序（应标注"需管理员"）
- **验证**：注册型 18 款归属准确率 100%；三个负例均未产生错误归因

### 任务 19：快速识别模式（可选 · P2 · 可延后）
- **文件**：`src/HotkeyTriage.Core/Discover/FastIdentify.cs`、`src/HotkeyTriage.Hook/HookDll.cpp`
- **要做**：
  - 新增一个 **C++ 原生 DLL 项目**（钩子必须原生实现，C# 做不到 `WH_GETMESSAGE` 的跨进程注入）
  - DLL 内捕获 `WM_HOTKEY`，通过共享内存回传 `{PID, 修饰键, VK}`
  - 主程序负责：环境闸门（提权/反作弊/用户确认）→ 按位数分组注入 → `SendInput` 逐个模拟 → 汇总 → 卸载
  - 硬编码排除：游戏进程、反作弊组件、屏幕阅读器
  - 收尾强制释放全部修饰键
- **验证**：
  - 对微信 / 钉钉 / Snipaste 三个已注册热键的进程，识别准确率 100%，且**过程未关闭任何进程**
  - 断言游戏与反作弊进程的注入列表为空
  - 断言结束后无残留钩子（任务管理器无异常模块）、无卡住的 Alt/Ctrl（手动验证）
  - 未提权运行时断言直接拒绝启用并给出提示
- **为什么放最后**：它需要引入 C++ 项目与第二个二进制，工程复杂度显著上升；而 §7.5 的遍历范围优化能拿到 80% 的收益（40 秒 → 10 秒），成本几乎为零。**先做优化，再考虑注入。**

## 5. 测试策略

### 5.1 TDD 适用范围

| 层 | 是否 TDD | 说明 |
|---|---|---|
| `HotkeyTriage.Core` | **强制** | 纯逻辑、依赖可注入。先写失败测试再实现 |
| `HotkeyTriage.App` | 不强制 | 用人工验证清单替代 |

**三个必须可测的设计**：

1. `HotkeyProbe` 走接口注入，测试时用 Fake 替代真实 `RegisterHotKey`
2. `DeepScanner` 的进程控制与探测都走接口注入，测试用内存假数据构造"关闭后某键释放"的场景
3. `KnowledgeBase` 从 `Stream` 加载，便于构造损坏输入

### 5.2 必须覆盖的断言（其余不追覆盖率）

| 断言 | 为什么必须 |
|---|---|
| `Guard` 对 `explorer`/反作弊返回 `Forbidden` | 一条错就可能毁桌面或封号 |
| 深扫后所有进程都已恢复 | 否则用户丢了程序 |
| 关闭前快照已落盘 | 否则异常退出后无法恢复 |
| `Free` 分支不触发任何关闭 | 否则会无意义地关掉用户程序 |
| 知识库缺失时功能不降级 | 这是"可取消"的验证条件 |
| 中止深扫后当前进程已恢复 | 最常见的残局来源 |

### 5.3 手工验证清单

| 场景 | 期望 |
|---|---|
| 启动后的「Windows 自带」tab | 分组正确，`Win+G` 标注可关闭，`Alt+Tab` 标注不可禁用 |
| 未深扫时的「其他应用」tab | 只显示数量与引导，不显示任何归属 |
| 深扫确认框 | 列出待关闭程序，`explorer`/反作弊不在列但被说明"不会触碰" |
| 深扫过程 | 可见进度、可中止、UI 不卡死 |
| 深扫完成 | 每个热键都归到正确进程，无残留未归因（除已声明例外） |
| 深扫中途中止 | 当前进程已恢复，已完成结果保留 |
| 禁用微信后 | 节点变「已禁用」，该热键从列表消失，微信进程确实退出 |
| 点恢复 | 微信重新出现，热键重新出现在列表 |
| 关掉工具再打开 | 提示上次禁用未恢复项 |
| AutoHotkey 吞键 | 不归因到 AHK（它不注册热键），列表里没有它 |
| 中文输入法激活 | 相关键不出现或被标为"系统/输入法" |

| 深扫关闭了有未保存内容的程序，用户丢数据 | **高** | 有窗口者默认不勾选 + 确认清单明示 + 优雅关闭优先 + 快照前置 |
| 深扫中途崩溃，多个程序未恢复 | **高** | 逐个立即恢复（非最后统一恢复）+ 启动时检查未恢复项 |
| 用户机器有反作弊，工具被误判 | **高**（v3.2 提权后升级） | 零注入零驱动 + 反作弊进程硬编码拦截 + README 声明为何需要管理员 + 不在游戏运行时自动动作 |
| 杀软误报 | **高**（"高权限+枚举进程+结束进程"是高危行为组合） | 代码签名；提交主流厂商白名单；README 提供 SHA256；避免无意义的高频进程操作 |
| H3 延迟比预期大，深扫超时 | 中 | T0 先测；必要时改为"同时关闭一组、批量复测" |
| UAC 门槛导致用户放弃使用 | 中 | 首次启动说明"为什么必须管理员"；README 前置说明；不做二次弹窗 |
| 用户误以为"提权了就能看到一切" | 中 | 关于页显式写明"管理员买的是覆盖面，不是读取特权" |

## 10. 范围防蔓延清单

| 想做的事 | 为什么不做 |
|---|---|
| 加开机自启常驻监控 | 与"双击即用、退出无残留"冲突；常驻引发反作弊顾虑 |
| 把注入模式设为默认 | 注入必须显式开启；默认永远走遍历 |
| 用内核驱动提升速度 | 驱动永不破例，任何模式下都不加载 |
| 支持实时监听热键变化 | 需要常驻或钩子，与上条同因 |
| 在管理员权限下做任何文档未声明的系统修改 | 提权只用于"读取信息 + 结束目标进程"，不得改注册表 / 服务 / 驱动配置 |
| 做键位重映射 | PowerToys 已做得更好 |
| 加"优化建议/清理"等周边功能 | 偏离单一职责，增加维护面 |
| 支持 Win7/8 | 目标用户系统不会那么旧 |
| 做安装包/自动更新 | 单文件就是最好的分发；纯离线是定位 |

**判断标准**：任何让「零注入、零驱动、可恢复」这三条被打折的功能，都不做。（"必须管理员"已是 v3.2 既定前提，不在此列。）
